# Changelog

All notable changes to this project will be documented in this file.

## 0.5.0

- New `--lint-kyverno DIR` and `--lint-conftest DIR` (both repeatable) lint rendered manifests with the policies in DIR directly — argocdf runs the tool and parses its report itself, so the shell pipeline and the `jq` stage go away entirely, along with the two ways an adapter is usually written wrong: treating empty output as failure, and treating a findings exit as a crash. `kyverno apply` is pointed at the cluster being diffed automatically and refuses to run rather than fall back to the ambient one. DIR is repo-relative and resolved per side, so a PR that changes a policy lints each side with its own version; a side where the directory is absent (the base of a PR adding the first policy) is skipped rather than failed, and a directory missing from the working tree is warned about at startup so a typo cannot read as "no findings". `--lint` remains for any other tool. Output is byte-identical to the equivalent shell adapter, which argocdf's e2e suite pins by running the same fixture both ways
- `--lint-timeout` now defaults to 10s (was 5s), and every invocation's duration is logged at INFO (`Linted rendered manifests app=… side=… duration=… findings=…`). The old budget was sized for an offline policy engine, but the adapters this project recommends are cluster-aware (`kyverno apply --cluster`, `kubectl --dry-run=server`) and pay for an API discovery per invocation — with `--concurrency` running several at once, the tail is contention rather than tool speed. Measured against a real ArgoCD cluster: ~0.3s warm and ~1.4s cold when serial, but ~1.4s each with four in flight, which tipped healthy runs over 5s and attached `lint "…": timeout after 5s` warnings to apps whose tooling was fine. A timeout only bounds a hung adapter, so the headroom costs nothing, and the logged duration is what a bare timeout warning never told you

- `--lint` commands now learn which cluster argocdf is diffing: every command runs with argocdf's environment plus `ARGOCDF_CONTEXT` (the resolved kube context — the `--context` value, or the kubeconfig's `current-context` when the flag is unset, so adapters need no fallback logic) and `ARGOCDF_KUBECONFIG` (the kubeconfig argocdf itself read: `--kubeconfig`, else `$KUBECONFIG`, else `~/.kube/config`). Cluster-aware adapters (`kyverno apply --cluster`, `kubectl apply --dry-run=server`) previously validated against whatever cluster the invoking shell pointed at, which in CI is rarely the one under review. Neither variable is ever exported empty — an unresolvable value is simply absent, so a cluster-aware adapter should require `ARGOCDF_CONTEXT` and fail when it is missing rather than carry on against the ambient cluster and report findings about a different one — and an inherited value is REPLACED rather than shadowed (a duplicated environment key resolves to its first occurrence in the child, so a stale `ARGOCDF_CONTEXT` from the environment would otherwise beat `--context`). `KUBECONFIG` itself is left untouched
- Fix (`--renderer=argocd`): kustomize spec overrides no longer leak between applications pointing at the same repo path. ArgoCD's kustomize pipeline applies `spec.source.kustomize` fields (namePrefix, images, patches, ...) by rewriting `kustomization.yaml` in the source directory; argocdf renders every app of a side from one shared worktree, so after an app with overrides rendered, a later render of the same path picked its mutations up — which app won depended on render order, so two same-path apps (one with overrides, one without) rendered nondeterministically across runs. The engine now snapshots the kustomization file before each render and restores it afterwards (also on render failure). The native renderer was never affected — it always copied the tree before editing
- Fix: logging from argocdf's libraries no longer pollutes output with foreign formats. ArgoCD's per-command exec tracer (a JSON `Trace` line for every helm run — emitted by BOTH engines via the shared chart client, previously silenced only under `--renderer=argocd`) and client-go's expected watch-cancellation error after credential loading are quiet by default; under `--verbose` everything stays visible, re-emitted through argocdf's own logger with source prefixes (`argocd:`, `client-go:`) in the same timestamped format as the rest of the log. client-go's very verbose internals (V>4, e.g. request-body hexdumps) are dropped, its remaining chatter maps to debug level, and the reflector's "Failed to watch: context canceled" — argocdf's own deliberate informer shutdown, not a failure — is demoted to debug so errors mean something. An explicitly set `ARGOCD_LOG_LEVEL`/`ARGOCD_LOG_FORMAT` is always respected (`ARGOCD_LOG_LEVEL=info` remains the render-debug channel even without `--verbose`)
- Fix (`--renderer=argocd`): OCI registry credentials no longer flow through `helm registry login`/`logout` — the engine writes them to a private per-run registry config (0600, removed at exit) and points `HELM_REGISTRY_CONFIG` at it, handing ArgoCD's code credential-stripped repository entries so its login/logout never execs. This fixes two failure classes on developer machines: helm's credential store silently upgrades to the platform native store when a `docker-credential-*` helper is in PATH (on macOS every login landed in the shared system keychain, where concurrent renders' login→build→logout cycles raced — `errSecDuplicateItem (-25299)` on colliding logins, and spurious 401s on private OCI chart dependencies when one render's logout deleted the credential another render's `helm dependency build` was using), and the token no longer appears on helm's argv (`--password`), in the user's keychain, or in the user's registry config. `--repo-creds=local` is unaffected: it keeps reading your own registry config (including credential helpers), still read-only
- Fix (`--renderer=argocd`): inherited helm environment variables (`HELM_CONFIG_HOME`, `HELM_REPOSITORY_CONFIG`, `HELM_REGISTRY_CONFIG`, ...) are scrubbed from the engine's environment. ArgoCD isolates its helm executions by appending per-command temp-home variables, but a duplicated environment key resolves to its FIRST occurrence in Go binaries like helm, so an exported `HELM_CONFIG_HOME` silently redirected the engine's dependency builds and registry auth into the user's helm state (defeating the isolation the engine documents). The native renderer keeps its ambient-environment semantics unchanged
- Reports are now deterministic run-to-run: application sections are sorted by (namespace, name) in every output format. Previously the order followed Go map iteration and changed on each invocation, which made reports impossible to compare byte-for-byte (e.g. storing expected outputs in tests, or diffing two runs)
- Report footers now stamp provenance: `Generated at <timestamp> by argocdf v0.5.0 (abc1234 → def5678)` — the argocdf version and the resolved base → target commits. A posted PR comment or archived report permanently self-describes what produced it (CI artifacts expire; comments don't). Terminal output keeps no footer
- Add `--repo-creds cluster|local|none` (env `ARGOCDF_REPO_CREDS`, default `cluster`): where repository credentials come from. `cluster` reads ArgoCD's repository secrets and credential templates from the control-plane namespace through ArgoCD's own `util/db` code and feeds them into rendering exactly the way the application controller does — private OCI/helm chart sources then authenticate with zero local helm setup, and private chart dependencies do too under `--renderer=argocd` (the native renderer builds dependencies in your local helm environment). The same credentials authenticate git clones of external repositories referenced by multi-source apps and apps-of-apps children (HTTPS basic auth/bearer tokens via a header carried in the environment, never argv). It needs `get,list,watch` on Secrets and ConfigMaps in the ArgoCD namespace; a read failure aborts the run with a message naming the alternatives (no silent degradation), while a cluster without repository secrets simply renders credential-less as before. `local` uses your helm config instead: repositories.yaml entries (classic repos store credentials inline there) plus your `helm registry login` state for OCI — including credential helpers such as the macOS keychain — and never writes to either. `none` renders anonymously (the pre-0.5.0 behavior). All three modes run the identical render pipeline; they differ only in what fills the credential lists
- Remote chart downloads in BOTH engines now go through ArgoCD's own chart client (`util/helm.Client.ExtractChart`, the repo-server's chart-fetch path) wrapped in argocdf's persistent chart cache — OCI-vs-classic dispatch, registry login, username/password, TLS client certs, `insecure`, and proxy handling all come from ArgoCD's code instead of hand-built `helm pull` commands. Relative value files packaged in a remote chart now resolve against the extracted chart (as ArgoCD does), and remote-chart renders match ArgoCD's `ARGOCD_APP_NAME`/`ARGOCD_APP_PROJECT_NAME` and default release names, including `<namespace>_<name>` instance names for apps outside the control-plane namespace
- Fix: renderable sources living in OTHER git repositories (multi-source apps, apps-of-apps children) now render from their own checkout at `targetRevision` instead of an identically named path in the local worktree. This includes the orchestrator's missing-source-path check: external git sources were previously stat'ed against the LOCAL worktree, so a discovered child sourcing another repo rendered empty on both sides and reported "No changes" — hiding the real diff entirely (caught by the e2e hollow-pin audit; the external clone path was unreachable before this)
- Apps-of-apps children REMOVED between branches are now reported as deleted applications: the child renders from its base-branch spec and every one of its resources shows as removed, symmetric with how added children have always been reported (previously only the parent's Application resource removal was visible — the child's actual workloads silently vanished from the report). Removed grandchildren cascade recursively, bounded by the same discovery depth limit
- BREAKING: `--namespace`/`-n` and `ARGOCDF_NAMESPACE` are replaced by `--argocd-namespace` (env `ARGOCDF_ARGOCD_NAMESPACE`): the ArgoCD control-plane namespace (default `argocd`) — repository secrets are read there and Applications are listed there by default. The `-n` shorthand is dropped on purpose so old invocations fail loudly instead of silently changing meaning. New `--application-namespaces` (env `ARGOCDF_APPLICATION_NAMESPACES`, comma-separated; entries may be literal names, globs like `team-*`, or `/regex/`, matched with ArgoCD's own pattern matcher): when set, the EXHAUSTIVE list of namespaces scanned for Applications — include the ArgoCD namespace explicitly if wanted. This deliberately deviates from argocd-server's additive semantics because a CLI runs under the user's RBAC, which may not include the ArgoCD namespace at all: an all-literal list is served by per-namespace reads (namespace-scoped RBAC suffices), while pattern entries require a cluster-wide list (as `-A` always did). `-A/--all-namespaces` is now sugar for `--application-namespaces='*'`
- `--helm-add-repos` and `--helm-skip-refresh` are marked "(native renderer only)" in `--help`, and explicitly setting either together with `--renderer=argocd` logs a warning — the argocd engine registers chart dependency repositories itself, inside its isolated helm home
- Add `--renderer` (env `ARGOCDF_RENDERER`): select the render engine. `native` (default) keeps argocdf's own helm/kustomize pipeline; `argocd` renders through ArgoCD's actual repo-server code (`reposerver/repository.GenerateManifests`, the `argocd app diff --local` code path) for exact ArgoCD parity — helm runs with `--include-crds` (CRDs from `crds/` show up in diffs), every `spec.source.helm`/`kustomize` field is honored with ArgoCD's own translation, `$ARGOCD_APP_*` build-env variables are substituted (fed from the rendered commit), `.argocd-source*.yaml` overrides are merged, and helm dependency repos from `Chart.yaml` are registered automatically in an isolated temp helm home (no user helm config is touched; `--helm-add-repos`/`--helm-skip-refresh` don't apply to this engine). argocdf still handles worktrees, remote-chart fetching (with the persistent chart cache), `$ref` source checkout, and render caching (engines never share cache entries). Set `ARGOCD_LOG_LEVEL=info` to surface ArgoCD's per-command exec traces for render debugging. Binary grows ~85MB from linking the repo-server code
- Fix: chart sources with scheme-less OCI repository URLs (e.g. `ghcr.io/org` — how ArgoCD stores OCI repos, with `enableOCI` on the repository secret) are now pulled as OCI charts in both engines. Previously they were treated as classic HTTP repos and `helm repo add` failed with "could not find protocol handler". A scheme-less URL can never be a classic chart repository (those require `http(s)://`), so OCI is the only valid interpretation
- Add a cross-engine behavioral test suite (`TestEngineBehaviorParity`) running every rendering scenario — helm values/parameters/release-name/namespace/kube-version/api-versions/schema-validation/chart-autodetection, kustomize overrides (namePrefix, namespace, images, commonLabels, relative bases), directory sources (plain, recursive, JSON), multi-source concatenation and `$ref` value files — against BOTH engines, with intentional differences pinned per engine: the `argocd` engine includes chart `crds/` (`--include-crds`) and, matching real ArgoCD, does not skip hidden directories in recursive directory sources (the native engine skips them)

## 0.4.0

- Add `--lint` (repeatable; env `ARGOCDF_LINT` for a single command) and `--lint-timeout` (default `5s`): pipe each affected app's rendered manifests through user-supplied shell commands and report their stdout as warnings. Each side (base and target) is linted separately — the command runs with that side's worktree as its working directory, so repo-relative policy paths resolve to the branch's own files — and every non-empty stdout line becomes a `[base]`/`[target]`-labeled warning in all output formats, alongside the existing parse warnings — a `[base]`-only finding was fixed by the change under review, `[target]`-only was introduced, both sides = pre-existing. Any policy tool plugs in through a jq-style adapter (kyverno, conftest, kubeconform, ...); argocdf never parses tool-specific output. A command failure (spawn error, timeout, or exit ≠ 0) is reported as a non-fatal warning line — stdout lines received before the failure are kept

## 0.3.0

- Add `split[=N]` file-output option for `md-fields`/`md-unified` (e.g. `-f md-unified,split:pr-comment.md`): a report larger than N bytes (default 60000, safely under GitHub's 65,536-char comment cap) is written as multiple self-contained part files (`pr-comment.md`, `pr-comment.2.md`, ...) instead of one oversized file. Each part carries the upsert marker and a `part i/N` heading with balanced `<details>` blocks and code fences, so CI can post every part as its own PR comment. An app's report stays within a single part; only an app that alone exceeds the limit is split at resource boundaries, and only a single resource diff larger than a whole part is truncated (with a note). Stale part files from a previous, larger run are removed automatically.
- Add `--helm-add-repos` (env `ARGOCDF_HELM_ADD_REPOS`): make chart dependency HTTP(S) repositories resolvable before `helm dependency build`, deduplicated per run. A URL already registered under any name is only refreshed (`helm repo update <name>`) — no new repositories.yaml entry; unknown URLs are added under a collision-proof `argocdf-dep-<hash>` name. Note it mutates local helm state either way (index caches, and repositories.yaml for unknown URLs), hence off by default; intended for ephemeral CI runners where the helm repo cache is empty
- When `helm dependency build` fails because a dependency repository is not registered ("no cached repository" / "no repository definition"), the error now includes an actionable hint listing the repos to `helm repo add` and pointing at `--helm-add-repos`
- Update the GitHub Actions examples: both workflows render with `split` and post each part as its own comment, and pass `--helm-add-repos` for fresh-runner chart dependencies; `wf-extra.yaml` drops its oversized-comment truncation step
